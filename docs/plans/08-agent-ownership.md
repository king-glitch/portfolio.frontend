# 08 — Parallel agent ownership (conflict rules)

Applies to every implementing agent. No git, no worktrees: all agents share one working tree, so **file ownership is the only conflict guard**. Approved answers: overview §13 recommendations (Q1–Q12 all "yes/as recommended").

## Waves

1. **F** (alone): Foundation + milestone 1 (plan 02) **plus the shared seeds below**.
2. In parallel, after F: **S** (plan 03 shell), **H** (plan 04 home), **P** (plan 05 project page), **A** (plan 06 part A about), **N** (plan 06 part B notes).
3. **T** (alone, after wave 2): plan 07 terminal + all passes + final gate + `graphify update .` + MEMORY.md.

## Shared seeds F must create so later agents never edit shared files

- `package.json`: every dep and script in plans 02–07 (deps: `@tanstack/react-query`, `i18next`, `react-i18next`, `zod`; scripts `check`, `typecheck:scripts`, `lint:tw`, `lint:style`, `pretty`, `build:tokens`, `build:portfolio`, `build:locales`, `test`).
- `src/config.ts`: **complete**: routes, `queryKeys.portfolio.*`, `mock.latencyMs`, and sub-objects `shell`, `home`, `work`, `about`, `notes`, `terminal` holding **every tunable number named in plans 03–07**. Others only read it. A missing key = add it inside your own sub-object with one small `Edit` (`config.<your-domain>.*` only); never touch another domain's block.
- `src/routes.ts`: all 7 routes registered; every route file exists as a typed placeholder (so `.react-router/types` is generated once). Owners replace file contents only.
- Locales: **`src/locales/parts/<ns>.json`**, one file per top-level namespace (`common, shell, home, work, about, notes`); `scripts/build-locales` merges them into `src/locales/en.json` (sorted, Prettier-formatted, deterministic) via `bun run build:locales`. Agents edit **only their own part file(s)**, then run `bun run build:locales`. (Deviation from "single en.json": en.json stays the single runtime source; parts exist only to avoid concurrent writes. Record in MEMORY.md.) `i18next.d.ts` types from `en.json`.
- CSS: `src/main.css` imports pre-created `src/theme/{page-transition,print,home,work,about,notes}.css` (empty placeholders) from F. Agents write only their own file.
- shadcn primitives: F adds all of `dialog, sheet, skeleton, alert, empty, toggle-group, input-group, badge`. Nobody else runs `shadcn add`.
- Shared components/hooks created by F (so wave-2 agents only consume): contexts `preloader-context`, `shell-context`; hooks `use-raf`, `use-reduced-motion`, `use-scramble`; `common/typography/{section-label,display-heading}`; `common/buttons/*`; `common/feedback/*`; `common/art/*`; `shared/posts/{post-card,post-card-skeleton}`; `shared/projects/project-preview-card`; `shared/contact/contact-links`; `src/types/*` shared enums; `lib/routes.ts`; all api types/hooks/mocks.

## Rules for wave-2 agents (S H P A N)

- Never edit a file you do not own. Need a change in a foundation file (F's) or another agent's file? **Do not edit**: describe it in your final report under "Requests".
- `src/components/ui/**` is generated; never edit.
- Do not run `bun run build`, `react-router typegen`, `graphify update .`, `bun run build:tokens`, `bun run build:portfolio`, or `bun run pretty` on the whole tree (shared outputs/other agents' half-written files). Allowed: `bunx tsc --noEmit` (filter output to your own paths), `bun test <your paths>`, `bunx prettier --write <your files>`, `bun run build:locales`, `bun run lint:tw`/`lint:style` (scope to your paths if the script supports it; ignore errors in files you do not own).
- Do not touch `MEMORY.md`; put notes in your final report.
- Strict AGENTS.md: `@/` imports, kebab-case, one component per file, enums not unions, no class-constant files, no nested ternaries, all strings via `t()` keys (add them to your part file), shadcn first (Base UI `render`), every async state handled, overlay lifecycle rules, ≤ 6 files per folder, `// ponytail:` marks.
- Browser verification: use the Bash tool to run `bun run dev` on **your own port** (`--port` S=5201 H=5202 P=5203 A=5204 N=5205) and verify with available browser tooling if any; otherwise state clearly that browser checks were not performed. Kill your dev server before finishing.
- Final report format: files created, acceptance checks done vs not done (be honest), Requests (changes needed in files you do not own), deviations.
